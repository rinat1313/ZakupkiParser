# Поступление задачи

Один общий skill на весь цикл. Роли — в субагентах (`.cursor/agents/`), не в отдельных skills.

## Порядок

### 1. Входная оценка (параллельно)

| Субагент | Зачем |
|---|---|
| `developer` | реализуемость, DataCode, СУБД |
| `analyst` | полнота ТЗ, 44/223-ФЗ, пробелы |
| `llm-specialist` | влияние на дальнейший LLM-анализ |

### 2. План — `lead`

Пул задач для developer + вне скоупа + запрет смены endpoints без разрешения.

### 3. Реализация — `developer`

Код только в `DataCode`, без комментариев.

### 4. Проверка (последовательно)

1. `tester` (код не меняет)
2. `llm-specialist`
3. `analyst`

### 5. Решение — `lead`

принято → мёрж в `main`; иначе доработка → шаг 3.

### 6. Отчёт — `lead`

сделано / не сделано / риски.

Шаблон: [references/report-template.md](references/report-template.md).

## Почему один skill

Процесс один — роли разные. Отдельные skills по специалистам дублируют порядок шагов. Новый skill — только для другого процесса, не для новой роли.
