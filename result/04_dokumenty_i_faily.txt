04. ДОКУМЕНТЫ И СКАЧИВАНИЕ ФАЙЛОВ
=================================
Образец: html/Сведения закупки документы.html
URL: /epz/order/notice/ea20/view/documents.html?regNumber=0134300097526000797


1. СТРУКТУРА ВКЛАДКИ
--------------------
.blockInfo
  h2.blockInfo__title              — группа документов
  .notice-documents.blockInfo__section
    .section__value.docName        — название документа/извещения
    .section__attrib / .section__value — «Размещено», «Редакция»
    .blockFilesTabDocs
      .attachment.row
        a[href*="filestore"][title] — файл для скачивания


2. ГРУППЫ ДОКУМЕНТОВ (ИЗ ОБРАЗЦА)
--------------------------------
- Извещение, изменение извещения о проведении электронного аукциона  ← есть файлы
- Изменение организации, осуществляющей размещение → «Информация отсутствует»
- Квитанции результатов согласования… → пусто
- Отмена определения поставщика… → пусто
- Разъяснения положений извещения… → пусто
- Протоколы работы комиссии → «Сведения отсутствуют»

Пустые группы — норма. Не считать ошибкой парсера.


3. URL СКАЧИВАНИЯ (FILESTORE)
-----------------------------
Шаблон 44-ФЗ (из образца):
  https://zakupki.gov.ru/44fz/filestore/public/1.0/download/priz/file.html?uid={UID}

Примеры uid из образца:
  019FBAF7032A7EEF8B947F799EBF9310  — Обоснование НМЦК 47,3.xlsx
  019FBAF6F4C67FE0A206CAC8B7AFECE5  — Проект контракта.docx
  019FBAF6FC1E75BE9A9B0CFF391888B4  — Описание объекта закупки 47,30.docx
  019FBAF6F1C877988B14FCADA3E2AC0E  — Требования к содержанию, составу заявки.docx

Имя файла брать из атрибута title у ссылки (не только из текста <a>).

Селектор:
  .attachment a[href*="/44fz/filestore/public/1.0/download/priz/file.html?uid="]

Внимание: сегмент /priz/ может отличаться для других типов документов.
Не хардкодить только priz — парсить полный href.


4. ПОДПИСИ / ПЕЧАТНЫЕ ФОРМЫ
--------------------------
Список подписей документа:
  /epz/order/notice/signview/listModal.html?reestrNumber=...&documentNumber=...

Подпись файла:
  /epz/order/notice/signview/ep/listModal.html?reestrNumber=...&uid={UID}

Печатная форма версии:
  /epz/order/notice/printForm/viewByVersionNumber.html?regNumber=...&versionNumber=1&qualifier=regNumberAndVersion


5. РЕДАКЦИИ
-----------
На странице есть переключатель «Отображать недействующие редакции»
(#revisionViewToggle / .inactive-redaction-toggle).
По умолчанию — действующая редакция.
Для аудита истории может понадобиться включать недействующие.


6. АЛГОРИТМ ЗАГРУЗКИ В ПРОДУКТ
------------------------------
1. GET documents.html?regNumber=...
2. Найти все a[href*="filestore"][href*="uid="]
3. Для каждого файла сохранить:
     reg_number, filename (title), uid, full_url, group_title,
     placed_at, edition_status, downloaded_at, sha256, size, storage_path
4. Скачать GET по full_url (тот же rate limiter, что и для HTML)
5. Retry при пустом теле / 429 / сетевых ошибках
6. Класть blob в object storage / ФС; в СУБД — метаданные + путь/ключ


7. СВЯЗЬ С КОНТРАКТОМ
---------------------
Документы извещения ≠ акты приёмки контракта.
Акты — на document-info.html контракта (когда контракт уже заключён).
Для скоринга заказчика акты важны отдельно (дата фактического закрытия).


8. ЛОВУШКИ
----------
- В поиске ссылка «Документы» иногда ведёт на eap20/okp20, а вкладки карточки — на ea20.
  Следовать tabsNav текущей карточки.
- «Информация отсутствует» — валидный ответ UI.
- Не все нужные поля есть в XML printForm — вложения почти всегда из HTML.
- Скачивать только публичные filestore-ссылки; не эмулировать личный кабинет без нужды.
